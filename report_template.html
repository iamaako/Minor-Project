1. Executive Summary & Purpose

In high-stakes university programming examinations, visual cheating (such as glancing at adjacent candidate screens or conferring with the student seated next door) represents a common academic integrity challenge. The AI Webcam Proctoring & Neighbor Detection module addresses this by introducing continuous, on-device facial landmark and head-pose analysis that monitors candidate attention in real time.

2. Key Highlights

100% Offline On-Device Computer Vision

The system runs entirely within the student's Electron client environment without making external cloud API calls. Neural network weights (TinyFaceDetector and FaceLandmark68) are packaged locally in the application bundle, satisfying strict air-gapped lab network requirements.

Biometric Facial Symmetry & Head Yaw Tracking

By extracting 68 facial landmark coordinates 7 to 8 times per second, the algorithm tracks the relative position of the nose tip relative to both eye corners. This enables precise differentiation between natural screen viewing, glancing down at a keyboard, and turning sideways to view an adjacent student's terminal.

Multi-Stage Violation & Grace Period Lifecycle

To prevent false positives from natural blinking or brief neck adjustments, infractions are managed via a multi-tier threshold: minor glances (< 1.0s) are ignored; sustained turns (≥ 1.0s) trigger an amber warning indicator; persistent turns (≥ 2.0s) record an official violation, trigger an evidentiary snapshot, and alert the invigilator.

Floating Windows XP Picture-in-Picture (PiP) Interface

Students are provided with a draggable, minimizable Picture-in-Picture window styled in the native Windows XP visual design. The live video stream includes face bounding boxes, direction markers (✓ SCREEN FOCUS, ⚠ LOOKING RIGHT, ⚠ LOOKING LEFT), and real-time status diagnostics.

Automatic Evidentiary Snapshot & Teacher Server Synchronization

Upon confirming an infraction, the application captures a compressed JPEG webcam frame and transmits it alongside timestamp, seat number, and roll number to the Teacher Admin Server via Socket.io for immediate invigilator review.

3. How It Works: Technical Architecture

The proctoring pipeline follows a real-time cycle: Frame Capture → Offline Tensor Processing → Geometric Yaw Estimation → Temporal Smoothing → Alert Dispatch.

📷 1. Frame Ingestion

Captured via navigator.mediaDevices.getUserMedia at 320×240 resolution (15–20 FPS). Camera permissions are granted silently by the Electron main process via session handlers without prompting dialogs.

🧠 2. Neural Landmark Detection

WebGL-accelerated TinyFaceDetector locates face bounding boxes, followed by FaceLandmark68Net mapping 68 anatomical coordinates across jawline, eyes, nose, and mouth.

📐 3. Mathematical Yaw Calculation

Evaluates horizontal displacement of Nose Tip (Point 30) relative to the Eye Centerline midpoint and the Euclidean distances to the Left Eye (Point 36) and Right Eye (Point 45).

🚨 4. Alert & Evidence Dispatch

Upon exceeding the 2.0s threshold, an offscreen canvas extracts a 320×240 JPEG evidence snapshot, notifies the student with a warning banner, and emits a socket event to the teacher's dashboard.

Mathematical Formulation

Symmetry Ratio = Distance(Nose Tip, Right Eye Outer) / Distance(Nose Tip, Left Eye Outer)
Nose Offset X = (Nose Tip X - Eye Midpoint X) / Eye Span Width

Decision Boundary Thresholds:

  • Facing Screen (Normal): 0.60 ≤ Symmetry Ratio ≤ 1.65 and |Nose Offset X| ≤ 0.16.
  • Looking Right (Neighbor on Right): Symmetry Ratio > 1.65 or Nose Offset X > +0.16.
  • Looking Left (Neighbor on Left): Symmetry Ratio < 0.60 or Nose Offset X < -0.16.
  • Candidate Absent / No Face: Face detector returns zero bounding boxes for > 3.0s.
